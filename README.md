# SetuHaul dock exception service

A conversational exception desk for truck drivers, wrapped around a deterministic capacity core.
Drivers report delays in free text; the system offers only slots that are genuinely feasible,
holds them properly, and escalates when there is no honest answer.

**The one rule the design turns on:** a language model reads text and writes text. It never decides
feasibility, never ranks two drivers against each other, and never commits a booking.

## Running it

```bash
python3 -m venv .venv && .venv/bin/pip install boto3 "botocore[crt]"
python3 scripts/audit.py          # deliverable 1 - data audit, 16 findings, each proven by query
python3 scripts/build_workdb.py   # copy the snapshot, add slot_locks / decision_audit / request_log
python3 scripts/race_test.py      # deliverable 5 - 20 concurrent claims on one slot, 10 repeats
.venv/bin/python scripts/run_scenarios.py   # deliverable 4 - the scenario ladder (needs AWS)
```

Only `run_scenarios.py` needs AWS. The audit, the working database and the integrity proof run
offline, which is deliberate: the part that must be correct does not depend on a model being up.

## Layout

```
docs/AUDIT.md                data audit, every finding with the query that produced it
docs/TRANSCRIPTS.md          the scenario run, generated by running the system
docs/INTEGRITY_PROOF.json    race-test results
docs/01..06                  metrics, decisions, performance, architecture, workflows, AWS runbook
src/setuhaul/capacity.py     the capacity lane. No model may be imported here.
src/setuhaul/agent.py        the conversation lane: boxes 1-6 and 11
src/setuhaul/prompts.py      system prompts, each stating what the model may NOT do
work/                        generated databases. Never the supplied snapshot.
```

The supplied snapshot is opened read-only and is never written to. It is evidence.

## What is proven, and what is not

Proven by running it: no double booking under 20-way concurrency, 10 runs out of 10; the escalation
case produces a complete hand-off record and detects that the facility's configured escalation
address matches no contact on file; a duplicate message replays instead of booking twice.

Also measured since: feasibility against an independently written SQL oracle (precision 1.0000,
recall 1.0000 over 72 cases, 1584 true positives, no false positives or negatives), and extraction
across four Nova models on 44 labelled cases, which is what chose nova-micro on BOOK precision
1.000. See `docs/07-EVALUATION.md`.

**Not proven by the deployment.** Each Lambda container keeps its own SQLite file in `/tmp`, and
two of them answer alternate requests, so the dock board and the audit trail can disagree between
refreshes. Reserved concurrency does not prevent this — it caps simultaneous executions, not the
number of warm environments, and measurement showed `audit_rows` moving 1 to 4 with no writes in
between. The integrity proof is `scripts/race_test.py` against a single database.
`docs/06-AWS-RUNBOOK.md` Part E has the measurement and the two fixes.

Still not measured: cost per resolved exception in money, accuracy on Hindi or transliterated
messages, and whether coordinators accept the automation rate in practice.
